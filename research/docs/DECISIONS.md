# Design decisions

Short records of choices that affect results. Keep this file updated when a
decision changes; the proposal is the reference for the protocol.

## D001 — Simulated snapshot is not research data

`data/raw/simulated_seed2026/` is generated by the PP1 simulator to exercise the
pipeline before ethics approval and recruitment. It contains observable fields
only; the hidden focus process is not exported, so no analysis can accidentally
use simulator ground truth.

## D002 — Label normalisation under leave-one-participant-out

The proposal defines "focused" as a learner's rating above their own mean
(z > 0) and a focus drop as z ≤ −1, with normalisation statistics fitted on
training data only (§3.2, §3.8).

For LOPO, the held-out participant has no training ratings. `RatingNormaliser`
therefore uses the **training-population mean and SD** for held-out participants
(`label_normalisation: train_population`). Using a participant's own test
probes would leak the test label distribution, so it is not done.

`within_learner` exists for EDA artifacts only (for example
`data/processed/labelled_epochs.csv`). Evaluation must pass a normaliser fitted
on the training fold.

## D003 — Missing features stay missing

The PP1 logger persists per-epoch aggregates, not key timestamps or app names
per switch. Seven proposal features cannot be computed from that snapshot
(`inter_key_mean_ms`, burst features, `click_rate`, `unique_apps`,
`app_category_entropy`).

They are written as `NaN` with `is_missing_<feature>` flags. They are never
filled with demo constants. Imputation, if used, happens inside the training
fold and is reported.

`inter_key_cv` and `backspace_ratio` are also set to `NaN` when fewer than
`min_keys_for_rhythm` (10) keys were pressed in the epoch. The PP1 simulator
fills those two with neutral constants for quiet epochs; the research pipeline
treats them as undefined instead, because rhythm and corrections cannot be
measured without typing.

## D004 — Application categories

Names are mapped to the proposal's coarse categories. A browser is
`browser_learning` for assignment and lecture sessions and `browser_other`
otherwise; the app name alone cannot reveal the page. Unknown names become
`other`. Only the category, never the window title or URL, is used.

## D005 — Typing bursts

A burst ends when the gap between consecutive key presses exceeds
`burst_gap_seconds` (default 2 s). Burst duration is the time between the first
and last key in the burst; a single-key burst has duration 0. Burst rate is per
minute.

## D006 — The app does not train

The PP1 browser model (logistic regression + k-means) is a demonstration
stand-in. The research pipeline is where the proposal's Gaussian HMM,
SVM/RF/XGBoost and per-fold validation live. Phase 5 exports the fitted model
and a feature contract so the app scores with the researched model instead of
training its own.

## D007 — State count when BIC is monotonic

On the simulated snapshot, median BIC keeps decreasing from 2 to 6 states: the
likelihood gain from splitting a continuous Gaussian emission is larger than
the BIC penalty at n = 6,600. `selection_summary` first looks for an interior
BIC minimum; when none exists it stops at the smallest k after which adding a
state improves median BIC by less than 10% of the total gain. The full BIC curve
and the rule are written to `state_manifest.json`, so the choice is auditable.
On real data the curve is re-checked; if an interior minimum appears, that k is
used.

## D008 — State features

The HMM uses the four features available for every epoch without imputation:
`typing_rate`, `idle_ratio`, `mouse_speed_px_s`, `switch_rate`. Event-only
features (`inter_key_mean_ms`, bursts, app entropy, clicks) are added after the
logger change. Fitting on imputed columns now would make state discovery depend
on the imputation model rather than on observed behaviour.

## D009 — Interruptions differ by study mode

In screen sessions an interruption is an interruption-like state (frequent
switching or idle/away). In non-screen sessions idle is the task — a learner
reading a book is not interrupting themselves — so an interruption requires
computer use: the frequent-switching state or typing at 10+ keys/min. The rule
is recorded in `state_manifest.json`; the per-epoch flag is `is_interruption`.

## D010 — Fixed state count in evaluation

The number of HMM states is selected once in Phase 3 and fixed at 4 for every
evaluation fold; the HMM parameters and scaler are refitted inside each fold.
Running BIC selection inside all 22 folds would add 22 × 25 HMM fits and make
the representation itself depend on the test participant. The state count is a
representation design decision, not a per-fold hyperparameter. If the BIC curve
changes materially on real data, re-run `make states` and then the experiments.

## D011 — LOTO measures task transfer, not participant generalisation

Leave-one-task-out trains on the other computer tasks using the same
participants, so a participant appears on both sides. Its higher scores must not
be compared with LOPO scores. LOPO is the participant-level result; LOTO answers
RQ2 (does the representation transfer to an unseen task).

## D012 — Fixed model settings

Classifier hyperparameters are fixed defaults (proposal 3.5), with balanced
class weights and a fixed seed. No tuning is done, so model capacity cannot
explain a representation difference. SVM is the reference model for the
ablation because it is the strongest linear kernel on this data; the full grid
is still reported for baseline vs proposed.
